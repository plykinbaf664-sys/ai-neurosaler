# Подключение Qwen

Все AI-функции бота используют одного выбранного провайдера: диалог, персональный маршрут,
вопрос перед аудитом и анализ материалов. Для Qwen не нужен ключ Anthropic.
Supabase, Telegram, календарь, библиотека и шар работают через существующие настройки.

## 1. Заполнить настройки

В `.env.local` уже подготовлен блок. Заполните его:

```env
AI_PROVIDER=qwen
QWEN_API_KEY=ваш_API_ключ
QWEN_BASE_URL=адрес_OpenAI_compatible_API_из_кабинета
QWEN_MODEL=qwen-plus
```

- **QWEN_API_KEY** — API-ключ доступа к моделям, созданный в кабинете провайдера.
- **QWEN_BASE_URL** — HTTPS-адрес совместимого Chat Completions API из того же кабинета.
  Это не адрес сайта с чатом. Можно вставить базовый URL или полный URL с `/chat/completions`.
- **QWEN_MODEL** — точный API ID доступной чат-модели. По умолчанию `qwen-plus`.
  Выбирайте модель с поддержкой `enable_thinking=false` и JSON output. Модели, работающие
  только в thinking/streaming-режиме, этому синхронному Telegram-flow не подходят.

Для Alibaba Cloud Model Studio ключ и endpoint должны относиться к одному региону.
Например, для Singapore адрес рабочего пространства имеет вид:

```text
https://YOUR_WORKSPACE_ID.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1
```

Замените `YOUR_WORKSPACE_ID` своим ID либо просто скопируйте готовый endpoint из кабинета.
Для другого региона скопируйте его адрес. Код не подставляет регион автоматически.
Актуальные адреса и правила ключей: [официальная документация Alibaba Cloud](https://www.alibabacloud.com/help/en/model-studio/compatibility-of-openai-with-dashscope).
Формат ответов: [JSON output](https://www.alibabacloud.com/help/en/model-studio/qwen-structured-output).

На сервере/Vercel добавьте те же четыре переменные в настройки окружения нужного deployment.
Локальный `.env.local` автоматически на сервер не переносится. После изменения переменных
перезапустите локальный процесс или выполните redeploy на хостинге.
Ключ хранится только на сервере; префикс `NEXT_PUBLIC_` ему не нужен.

## 2. Проверить подключение

Из корня проекта (Node.js 24, установленные зависимости):

```powershell
npm.cmd run ai:check
npm.cmd run ai:check -- --live
```

Первая команда проверяет заполнение полей без сетевых запросов. Вторая делает один короткий
платный запрос к выбранной модели и проверяет JSON-ответ. Успех:
`AI connection and JSON output: OK`. Проверка не пишет в CRM и не отправляет сообщения в Telegram.

Дополнительная проверка двух реплик с подбором материалов:

```powershell
node --env-file=.env.local scripts/check-dialogue.mjs --live
```

Она использует синтетического пользователя в локальной памяти и делает два AI-запроса.

На странице `/` и в `/api/status` отображается выбранный провайдер. Поле `ai.configured`
означает, что настройки заполнены корректно; баланс, доступ к модели и доступность API
проверяются только командой с `--live`.

## Если запрос не проходит

| Причина в выводе | Что проверить |
| --- | --- |
| `configuration_error` | Заполнить названную переменную; удалить шаблонные значения из URL |
| `authentication_failed` | Ключ и регион endpoint |
| `access_denied` | Активацию сервиса и доступ к модели |
| `model_or_endpoint_not_found` | Точный ID модели и адрес API |
| `insufficient_credits` | Баланс или квоту Qwen |
| `invalid_request` | Поддержку обычного чат-режима без thinking и JSON output |
| `rate_limited` | Лимиты провайдера; повторить позже |

При отказе Qwen бот сообщает о временной недоступности ответа, сохраняя запрос, маршрут и
материалы. Автоматического перехода на Anthropic и повторных платных запросов нет.
Запись на аудит через календарь остаётся доступной.

## Остальные шаги запуска этой версии

Настройки Qwen заменяют только AI-провайдера. Для новых функций маршрута/наград сначала
примените `supabase/sql/014_journey_and_audit.sql`, затем разверните код. Для напоминаний
нужны `LIBRARY_FOLLOWUPS_ENABLED=true`, `CRON_SECRET` и настроенный существующий cron.
Это не дополнительные требования Qwen: они относятся к предыдущим изменениям бота.
